## 4. 보류 항목: 스마트폰 통합 비행 E2E

### 4.1 검증 완료 범위

- 현재 노트북 LAN IP: `192.168.10.108`
- 모바일 HTTPS: `https://192.168.10.108:3443`
- 인증서 SAN에 현재 IP 포함
- Caddy health: HTTP 200 / `ok`
- 스마트폰 Chrome 카메라 권한 및 BROWSER_UPLOAD 전송 확인
- AI ingest accepted frame 증가 및 약 5 FPS 확인
- 테스트 중 신규 dropped frame 증가 없음

### 4.2 현재 중단 지점

- 스마트폰에서 긴 운영자 KEY 입력이 불편함
- 저장된 로그인 정보 사용 중 반복 인증 실패로 임시 로그인 잠금 발생
- 인증되지 않은 상태에서 통합 비행 시작 조건이 충족되지 않음
- 비행 시작 전 `완료 재시도`와 `비행 중단`이 비활성화되는 것은 정상 상태이나, `통합 비행 시작`의 정확한 비활성 조건은 인증 복구 후 재확인 필요

### 4.3 보류 중 금지 사항

- 장기 운영자 KEY를 URL 쿼리, QR 코드, 스크린숏 또는 문서에 기록하지 않는다.
- 임시 잠금 상태에서 로그인 버튼을 반복해서 누르지 않는다.
- 원인 확인 없이 인증서, Caddy 설정 또는 정상 컨테이너를 되돌리지 않는다.
- 스마트폰 검증을 위해 대량의 시연 데이터를 다시 생성하지 않는다.

### 4.4 3차 프로젝트 완료 기준

- 장기 KEY를 직접 입력하지 않는 일회용 페어링 방식 제공
- 권장안: PC의 ADMIN이 6자리 일회용 코드를 발급하고 스마트폰이 1회 입력
- 코드는 1회용, 유효시간 2분, 성공 즉시 폐기
- QR 사용 시 장기 KEY가 아니라 일회용 토큰만 포함
- 성공 후 HttpOnly 세션 쿠키 발급
- 스마트폰에서 OPERATOR 인증 상태 확인
- 통합 비행 시작 → 텔레메트리·카메라 전송 → AI 추론 → 비행 완료/중단까지 E2E 통과

## 7. 단계별 완료 정의(Definition of Done)

### 기능 완료

- 정상 경로뿐 아니라 권한 거부, 네트워크 단절, 카메라 거부, AI 지연, 중복 요청을 테스트한다.
- UI 상태와 서버 상태가 새로고침 후에도 일치한다.
- 테스트로 생성된 데이터의 소유 범위와 정리 방법이 명확하다.

### 운영 완료

- 실행·중지·백업·복원·인증서 갱신 명령이 문서화되어 있다.
- 실패 시 보고서 또는 로그 위치가 출력된다.
- 운영 스크립트는 비밀값을 출력하지 않는다.
- 예약 작업은 사용자 화면을 방해하지 않는다.

### 데이터 완료

- FK 고아 데이터가 0건이다.
- DB 참조 스냅숏과 실제 파일이 일치한다.
- 대량 생성 방지 게이트와 보존 정책이 자동 검증된다.

### 배포 완료

- Git 작업 트리가 깨끗하다.
- 원격 브랜치와 동기화되어 있다.
- acceptance, RBAC·Session, operational guard가 모두 통과한다.
- 검증된 최신 백업과 SHA-256이 존재한다.
